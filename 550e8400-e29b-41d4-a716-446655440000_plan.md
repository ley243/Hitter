# Plan: Fix Nerona Logs Not Displaying in panel.html

## Root Cause

The logs not appearing in `panel.html` are **not** caused by the narutox theme effects layer. Two research agents confirmed the effects layer is stacked at `z-index: 0` behind the panel `.wrap` at `z-index: 1`, and the narutox theme colors keep log text readable.

The real causes are upstream in the write pipeline for `chrome.storage.local['Nerona_logs']`:

1. **Overwrite race in `content-main.js`** — `syncLocalStorageLogs()` polls `localStorage['Nerona_logs']` every 1.2 seconds and **overwrites** the chrome storage array. `localStorage` only contains the auto-hitter's mirror, so it can clobber logs from the interceptor, 3DS relay, and network monitor.
2. **Read-modify-write races** — `content-3ds-relay.js`, `network-monitor.js`, and the auto-hitter each perform their own `GET → push → SET`, so concurrent writes can overwrite each other.
3. **Inconsistent auto-hitter schema** — `inject.js` log entries only contain `card`, `bin`, `response`, and `time`, missing `timestamp`, `type`, `site`, `url`, `source`, and `text`. This breaks `panel-history.js` rendering.

## Recommended Approach

Introduce a single, atomic **append bridge** (`Nerona_APPEND_LOGS`) in `content-3ds-relay.js` (isolated world, `document_start`). All producers send their entries to this bridge; the bridge reads the current `Nerona_logs`, merges new entries, deduplicates, sorts by timestamp, caps at 50, and writes the result back with `chrome.storage.local.set`.

This eliminates the overwrite race and the read-modify-write races while keeping the panel rendering code untouched.

## Detailed Changes

### 1. `script/content-3ds-relay.js` — add atomic append bridge

Replace `storeLogEntry` (lines 36-55) with `appendLogEntries`, keep the `Nerona_INTERCEPT_LOG` listener but route it to the new helper, and add a new `Nerona_APPEND_LOGS` listener.

```js
// Atomic append + dedup handler
function appendLogEntries(entries) {
  if (!Array.isArray(entries)) entries = entries ? [entries] : [];
  if (!entries.length) return;
  if (typeof chrome === 'undefined' || !chrome.storage || !chrome.storage.local) return;

  var now = Date.now();
  entries.forEach(function (entry) {
    if (!entry.timestamp) entry.timestamp = now;
    if (!entry.type) entry.type = 'log';
    if (!entry.source) entry.source = 'unknown';
    if (!entry.site) entry.site = (window.location && window.location.hostname) || '';
    if (!entry.url) entry.url = window.location.href;
  });

  chrome.storage.local.get(['Nerona_logs'], function (result) {
    var logs = Array.isArray(result.Nerona_logs) ? result.Nerona_logs : [];

    function dedupKey(e) {
      return Math.floor((e.timestamp || 0) / 1000) + '|' +
             (e.type || '') + '|' +
             (e.card || '') + '|' +
             (e.response || '') + '|' +
             (e.site || '');
    }

    var seen = new Set(logs.map(dedupKey));
    entries.forEach(function (entry) {
      var k = dedupKey(entry);
      if (!seen.has(k)) {
        seen.add(k);
        logs.push(entry);
      }
    });

    logs.sort(function (a, b) { return (a.timestamp || 0) - (b.timestamp || 0); });
    if (logs.length > 50) logs = logs.slice(-50);

    chrome.storage.local.set({ Nerona_logs: logs }, function () {});
  });
}

function appendRelayLog() {
  appendLogEntries({
    timestamp: Date.now(),
    type: 'three_ds',
    response: 'three_ds',
    site: (window.location && window.location.hostname) || '',
    url: window.location.href,
    source: 'relay',
    text: '3DS Bypass relayed'
  });
}
```

Update the existing `Nerona_INTERCEPT_LOG` listener to call `appendLogEntries(entry)` instead of `storeLogEntry(entry)`.

Add a new listener:

```js
window.addEventListener("message", function (event) {
  if (!event.data || event.data.type !== "Nerona_APPEND_LOGS") return;
  var entries = event.data.entries;
  if (!entries) return;
  appendLogEntries(Array.isArray(entries) ? entries : [entries]);
});
```

## Deduplication Rules

The bridge handler deduplicates using:

```js
Math.floor(entry.timestamp / 1000) + '|' + entry.type + '|' + entry.card + '|' + entry.response + '|' + entry.site
```

- Entries that match the same second, type, card, response, and site are considered duplicates and only one is kept.
- Different responses (e.g., an attempt log `"CARD+FP"` and a decline log `"do_not_honor"`) are kept as separate entries.
- Logs are sorted by `timestamp` ascending and capped at the last 50 entries.
